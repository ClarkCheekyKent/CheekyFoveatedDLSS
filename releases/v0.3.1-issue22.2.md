# DanceXR Eye Tracking Fix — v0.3.1-issue22.2

Fixes gaze mapping and rejected foveated DLSS passes in DanceXR, following the reports in [issue #22](https://github.com/ClarkCheekyKent/CheekyFoveatedDLSS/issues/22) and [issue #25](https://github.com/ClarkCheekyKent/CheekyFoveatedDLSS/issues/25).

## Changes

- Retains each native D3D12 DLSS feature's created output dimensions and uses its current render subrect for the input dimensions. This avoids treating values left by an optimal-settings query as the evaluation's output size.
- Finds calibration markers through vertically flipped submissions and applies the verified orientation to gaze, automatic alignment, and simulated jump indicators.
- Retains the R11G11B10_FLOAT calibration support and detailed failure reporting introduced in issue22.1; captures confirmed DanceXR uses this format.
- Preserves Streamline's tagged dimensions, restores the game's parameter values after evaluation, and retains marker-confidence, session, handle-lifetime, bounds, and GPU synchronization checks. Conflicting orientation evidence remains rejected.

## Validation

- User confirmed eye tracking works in DanceXR and verified compatibility in Assetto Corsa Evo.
- The installed DanceXR add-on matches the tested build by SHA-256, and its log records both eye mappings established through pixel markers.
- Full Release x64 build and automated tests passed, including gaze/geometry, DX11/DX12 calibration, OpenVR/OpenXR, UEVR lifecycle and ownership, and late attachment including Streamline.
- The complete candidate applies cleanly to upstream `492fbac` and passed a separate full build/test run with its OpenVR startup fix, including cached-compositor late attachment.
- GPU regressions cover flipped and unchanged HDR submissions, larger texture allocations, scaled array submissions, and rejection of conflicting orientations on WARP and hardware as applicable.
- Temporary full-texture capture instrumentation is removed.

## Installation

Close the game, back up the existing add-on outside the game folder, and replace only `CheekyFoveatedDLSS.addon64`. Keep the existing ReShade settings and Cheeky OpenXR layer. To roll back, close the game and restore the previous add-on.

The separate game-local ReShade loader and OpenXR Toolkit startup workaround used during the DanceXR investigation are not part of this code change. Validation covers the tested configurations, not every game or runtime combination.
